# Compatibility and verification

Date: 2026-10-16.

## Protocol sources

- Official Codex hooks documentation: https://developers.openai.com/codex/hooks (redirects to https://learn.chatgpt.com/docs/hooks).
- Native installed CLI: codex-cli 0.162.0-alpha.2. Its feature listing reports hooks stable/enabled.
- JSON schemas generated by that executable confirm hooks/list and native hook metadata. This does not by itself prove execution.

Codex hooks use hooks.json or inline config.toml hook tables. This installer manages hooks.json only. Non-managed definitions require trust. Codex command hooks apply to local orchestration; do not assume cloud sessions load local hooks.

## Native enforcement finding

The first local fixture returned exit code 2 and a ledger denial message, but the native CLI executed the shell write. Explicit JSON permissionDecision=deny prevented the write. Therefore all installed entries include --codex and the guards use structured decisions.

See [native-probe.json](native-probe.json) for recorded deny/allow side effects and exited subprocess IDs. This is actual Codex CLI enforcement using a deterministic localhost fixture, not a real model run.

The native apply_patch probe could not expose the tool reliably with the fixture profiles tried. It stopped at the correction limit. Native apply_patch enforcement remains UNVERIFIED. Direct tests cover patch input, multi-file changes, moves, deletion, brief text and explicit denial payloads.

The October 16 baseline did not verify Desktop activation. On October 18, the
updated kit was installed in the owner's active Desktop configuration. Real tool
calls demonstrated patch denial for an uncovered read target, publication-command
denial, local database-command denial, guest/test command allowance, and walkthrough
brief denial. Command probes used harmless local stubs; no release or database
mutation occurred. Rule injection and Stop double-check continuation were observed
in chat. This establishes those paths on this installation, not every Desktop tool.

The opt-in native worker adapter reads real parent/child relationships and lifecycle
records. Its snapshot matched the three setup workers' states. Evidence reporting
and completion-claim checking were exercised through installed entrypoints; that
does not establish all asynchronous Desktop delivery behavior. Automatic wake-up
and automatic resumption remain unsupported. See the focused configuration docs
linked from README for exact coverage and remaining limits.

Follow-up: the added completion gate's real CLI Stop continuation, correction, and terminal stop were exercised. [completion-probe.json](completion-probe.json) records the result. Its check caching avoids rerunning unchanged inputs. This does not establish Desktop activation or make the older marker-based gates stronger.

## Direct tests

Run npm test for original behavioral parity, disabled/scope behavior, installer preservation/idempotence/backup/uninstall, ledger counts, measurement freshness and native protocol adapters. The final test summary is in VERIFICATION.md.

The wake parity tests compare the worker classifications to the unchanged Claude reference while checking the intentionally different JSON informational output. They do not claim automatic wake parity.

## Known inherited limitations

- Ledger rows do not prove that the agent read or reused code.
- Absolute ledger paths are not constrained to upstreamRoots; duplicate rows are not deduplicated.
- Malformed project configs or regexes may disable a check.
- Shell matching is heuristic; arbitrary scripts, interactive input and other tools can evade coverage.
- Evidence/configuration and approval markers are ordinary editable files.
- Measurement uses timestamps and optional regex content, not code-bound proof.
- no-idle can request repeated continuations; it has no native shared budget.
- Deployment checks may fetch origin and trust configured receipt fields.
- Restoring hooks.json does not roll back overwritten hook script bytes.
- Tests run on Windows/Node 24.21.0. Node 18 and other operating systems have not been exercised here.
